**版本：CH01-PACK v1.0｜目标：以现有 Godot 4 工程为基础，一轮连续开发完成第一章约 80%–90% 的可玩内容，再进行集中试玩。**

## 确定不再反复讨论的玩法基准

- 地图探索使用 WASD；第一章偏剧情叙事，少量重要探索场景。
- **没有实时追逐、攻击、格挡、潜行系统**。普通感染者地图可见，**发生实体接触**才进入选项遭遇。
- 普通遭遇：逃跑概率/失败损 HP 与体力、武器耐久、防护物资、强行挣脱。**绝不触发感染**。
- 只有明确的特殊剧情高风险接触才可能感染暴露，且不会立即游戏结束。
- **一键回家：普通探索状态下无条件免费直接回家，绝无时间、风险、物资结算；任何已开始的危险遭遇/特殊事件必须先结算，期间禁止回家。**
- 负重影响携带容量及普通遭遇逃跑概率；维修武器需资源。
- 后期密度升高，玩法逐渐向安全屋与远程幸存者网络转移；第一章只做必要的接口与早期玩法，不一次实现后期全城系统。
- 不能把普通居民楼每层做成完整地图：楼内配送和1404多数通过剧情演出；精做 **出租屋 / 老城区街道 / 幸福花园外部 / 便利店室内**；楼道、电梯、猫眼使用轻量演出模板。
- **老周没有女主家钥匙**。老周认识女主并知道住处，是因曾带她入行、送她回家。门外人的身份直到电话与猫眼二次确认时才揭晓。

## 给 Codex 的使用顺序

1. 将整个文件夹放进项目（推荐 `docs/CH01_PACK/`），**不要替换现有脚本**。
2. 将 `00_CODEX_MASTER_PROMPT.md` 原文发给 Codex；要求读取本包全部文件。
3. Codex 一次连续完成 Phase 0–6，途中自行运行验证、修正和记录，**不要每个阶段停下来请求验收**。
4. 仅在遇到不可恢复的基础阻塞（缺失工程/不可访问依赖/无法保留数据）时暂停并给出阻塞报告。
5. 最终统一提交可运行工程、开发总结、测试记录、问题清单，用户集中试玩。

## 优先级说明

P0：第一章从开场到结尾可玩、剧情顺序正确、基础 UI 工作、地图可探索、无致命错误、读档能恢复。

P1：优质视觉演出、物品与分支反应、动态环境状态、音效与气氛。

P2：复杂地图细节、后期 NPC 网络、广域城市感染生态、多章内容。P2 **不允许挤占 P0**。

## 效果目标

“80%–90%”意味着主要**功能覆盖和剧情连贯度**，不是保证没有美术缺口、也不表示项目源代码尚未审查就可承诺实施成功。Codex 应在完成可执行验证的范围内报告真实进度。
