# CODEX MASTER PROMPT — 第一章连续开发任务（批量执行，不分段等待验收）

你是现有 Godot 4 / GDScript 游戏《人类暂未下线》的首席开发 Agent。本仓库内已提供 `HISO_CH01_Development_Pack`（如果移至 `docs/CH01_PACK`，以实际路径为准）；你**必须完整阅读全部 Markdown 与 JSON**，以包内规定为功能和剧情需求。当前目标是：**在一次连续开发会话中，把第一章做成从开场至章节结尾可完整试玩的版本，覆盖约 80%–90% 的功能与剧情，而不是仅输出方案或完成 5 分钟 demo。**

## 必须遵守的工作模式

1. **先读项目再动手**：实际检查 `project.godot`、入口场景、所有主要场景/脚本、资产、存档、订单/电脑聊天/UI/玩家控制逻辑、Git 状态和开发文档；不能假设功能存在或不存在。
2. **连续自主工作**：按 `04_execution/连续开发阶段与验收协议.md` 的 Phase 0–6 顺序实施，阶段内部自查、自测、继续下一阶段。**不要每完成一小项就让我确认，不要用“下一步可以做”代替执行**。仅当继续将导致数据丢失、缺失必要源文件或客观无法恢复的错误时停止。
3. **保留旧功能**：优先复用现有 WASD、订单、电脑版桌面、聊天和存档。新增手机应是已有聊天/订单的另一种 UI，不得平行维护两份数据。不要重写整个工程或破坏旧地图；必要时在兼容适配层扩展。
4. **剧情权威**：以 `01_design/CH01_剧情总纲与完整场景剧本.md` 与 `02_content/聊天_短信_新闻_订单素材.md` 为基准。不要自行改成全员重复说“你是不是一个人来的吗”，不要添加钥匙、灵异楼层、无因果的订单改址、平行时空、实时追逐或新主要人物。对未写死的衔接细节做最小合理补充并记录。
5. **地图策略**：先把“灰色空城”改成有内容的**小而密**的可玩街区。精做四个长期可复用场景：出租屋、老城区街道、幸福花园外部、便利店室内；楼道、电梯、猫眼轻量演出。不建设全栋居民楼室内或六个城区。
6. **战斗与回家**：感染者在街道可见，玩家与实体重叠/碰撞才触发普通遭遇；无主动追击 AI。普通遭遇只损生命/体力/道具/耐久，不感染。**普通探索始终可一键免费立即回家；已触发的普通感染者遭遇、便利店袭击、老周敲门等危险事件里不允许一键回家，必须先完成事件结算。** 没有任何回家途中的概率或物资结算。
7. **不静默伪造验证**：若无法运行 Godot 图形界面，不声称已视觉验收。尽可能用 Godot headless 启动、场景/脚本解析、单元/集成脚本、资源引用检查验证，真实记录成功/失败。无法验证者列入人工试玩清单。
8. **每个阶段留下记录**：更新 `docs/DEVELOPMENT_LOG.md`（若已有项目约定则沿用）、`docs/CH01_IMPLEMENTATION_STATUS.md`、`docs/CH01_TEST_REPORT.md`，至少记日期、改动文件、行为变化、验证命令/结果、已知问题、回退手段。可做本地 Git 提交以便回滚；**不自动 push，不覆盖用户未提交的改动，不执行破坏性 reset/clean**。
9. **缺少正式像素美术时的处理**：优先使用仓库现有资产。若缺素材，用风格一致的占位组合（不接受纯灰色方块空场景）；明确记录待美术替换资源 ID 与尺寸建议。不要假称生成了真实精细像素美术。
10. **批量执行而非等待确认**：从 Phase 0 直接推进到 Phase 6；如果 token/时间有限，优先保证一章贯通、内容完整、场景与界面可操作，P2 内容保留后续清单，最终如实列出覆盖比例估计及缺口。

## 验收目标：端到端主线

能从新档：夜晚街道配送→老周帮修车→出租屋打开电脑→骑手群铺垫1404→第二天普通配送→幸福花园调查（1404门口可选）→电梯异常男人（固定关键过场）→便利店同一个男人袭击陈姨、选项结算→回家手机/电脑新闻和老周失联→陌生雨衣人深夜敲门、多次猫眼、联系小鱼→电话显示老周→最终认人及隔门对话→多个有后果的剧情选择→凌晨城市危机升级和第一章结束标记。

**不要让玩家因为没有武器、没有查看1404、错过可选线索、过早一键回家而永久卡主线**；可以延迟事件或改用合理备用入口。

## 实施重点（详细拆分见包内文件）

- 统一剧情导演（flags / trigger / priority / execution / interruption / save）与数据驱动剧情；台词不可散落到各场景脚本。
- 手机：聊天、接单详情、地图（可最小功能）、新闻/通知；与电脑版共享数据、已读状态和进度。
- 电脑：在现有桌面上增量加入新闻窗口、桌面消息提醒、剧情派发消息，不破坏复古桌面。
- 统一对话/事件选项；一般 NPC 对话与危险遭遇可共享底层组件但有不同视觉风格。
- 负重、生命/体力、武器耐久、快速回家、碰撞触发遭遇、2 秒免重复弹窗、简单游荡感染者。
- 四个核心可复用场景通过交互/物资点/环境变化填充；剧情性楼道、电梯、猫眼用轻演出，不做多层完整居民楼。
- 章节场景演出：雨声、灯闪、隔门声、手机震动、消息逐条出现、便利店短促袭击、身份揭晓。采用可降级的演出：缺专用素材仍必须可玩。
- UI 与输入统一互斥：剧情/手机/电脑/遭遇/探索不得同时抢键盘；事件进行时禁止回家按钮；事件后恢复。
- 开发用调试跳转面板（可在 Debug 构建开启）：跳转到电梯、便利店、夜间消息、敲门、结局；自动补齐前置 flags、正确场景、时间、资源。

## 阶段执行

**Phase 0｜审计**：真实代码、资源、入口、冲突与 Git 现状；记录，不长时间停留在讨论。

**Phase 1｜剧情基础**：数据驱动 StoryDirector、稳定 flags、触发器、对话、选项、存档、事件互斥；把开头修车+骑手群跑通。

**Phase 2｜手机与电脑**：手机 UI、群聊/私聊同步、订单查看、新闻发布/弹窗、消息计时、存档恢复。

**Phase 3｜地图与室内**：四个可复用重点场景小而密地完善；楼道/电梯/猫眼轻演出；互动、碰撞、出入口、状态变化。

**Phase 4｜完整剧情**：从第0天到第2天凌晨所有主剧情、可选1404调查、电梯男人再次出现、便利店分支、夜间敲门揭晓、章末后果。

**Phase 5｜生存接入**：负重、武器耐久、碰撞遭遇、逃跑概率、伤害、无风险一键回家、危险事件禁止回家、第一章适度物资提示。

**Phase 6｜连续集成与测试**：自动验证、读档/重进、不同选择覆盖、调试跳转、兼容原配送、缺失美术回退，输出报告并修正阻断问题。

虽然以顺序列出阶段，若真实工程依赖关系要求先做少量 Phase 5 的基础接口，再写 Phase 4，应自行调整并说明。**阶段结束直接继续，不需用户分次确认。**
